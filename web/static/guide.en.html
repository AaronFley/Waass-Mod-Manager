Waass manages what lives in The Witcher 3's mods folder: enable/disable, install archives, load order, conflict checks, Nexus update checks, CN localization. It only ever touches what you click — files you haven't acted on are not modified by a single byte, and every write is preceded by a snapshot.

First launch

  1. Point it at your game folder. It looks for Steam, GOG and Epic installs on its own. If nothing turns up, the main screen walks you through it — pick the level that contains both a bin folder and witcher3.exe (not the mods folder underneath it, and not your save game directory). "Browse" opens the system folder picker; if that picker can't open on a given PC (rare), pasting the path into the field works just as well.
  2. Let the first scan finish. The list on the left is what's in your mods folder, the cards on the right show the details. The first scan backfills covers and author names; it takes well under a minute and won't stop you from using the app meanwhile.
  3. Watch the banner at the top. The amber one carries at most two items at a time, separated by a divider: "N mods not matched to Nexus" and "N mods have updates". Both come with a button that takes you where you deal with them. A separate orange banner counts "N things need attention" — that one is the banner for real problems. The very top one (green / amber / red) is the startup self-check: it speaks up when you just switched versions, when your data was migrated, or when a data file can't be read.

Enable / Disable

Open a mod card and use the enable / disable button in the detail panel on the right. Disabling prefixes the folder name with a ~ (modHoods becomes ~modHoods). The game only loads folders that start with mod and never even sees one starting with ~ — as if it were uninstalled, except nothing was actually removed.

Three reasons it works this way: it never touches mods.settings (a file that is notoriously picky about its format), it's a one-step switch back, and your load order (Priority) stays intact — re-enable a mod and it lands exactly where it was.

Installing new mods

"Import archive" in the top bar → pick a zip / 7z / rar (tar and gz work too) → read the preview first: it lists every file about to be written into your game folder and which of them overwrite existing files. Nothing is written until you confirm.

Before writing anything it snapshots mods.settings and the menu XMLs, so you can roll back afterwards. If the game is running, the install is refused outright — edits made mid-session get overwritten by the game, and can also cause trouble when loading save games.

Load order

That's "Load order" on the left. There is exactly one rule: lower number wins — this number is the Priority value in mods.settings.

When two mods change the same file, the one with the lower number takes effect. Equal numbers are undefined behavior; the app flags duplicates and asks you to separate them. Open "Load order" on the left — it lists enabled mods only: search by name, use the ↑ ↓ and ⇈ on each row to reorder, then press "Save order" to apply; disabled mods are folded to the bottom and take no part in the order.

Conflict detection

Only enabled mods are checked — disabled ones never load, so reporting them would be noise.

  • @wrapMethod: both mods want to hook the same function. In most cases they can coexist → reported as info only.
  • @replaceMethod: whichever loads later replaces the entire function → reported as a warning.
  • Inside bundles, only UI file clashes (ui / data) are reported. Materials and textures covering each other is business as usual — reporting that would just make you stop reading.

Script Merger: when two mods change the same script, it stitches them into a single "merged files" mod. Mods built for the Remastered version generally don't need merging — reach for it when you run a lot of legacy mods, or when the game throws script errors on launch. The app looks for it automatically within a bounded set of places — the game folder and nearby levels, Desktop and Downloads (with caching) — and shows the folder it found; if it's elsewhere or the wrong one was picked, choose it once via "Locate" / "Change folder" and it remembers.

Checking for mod updates

To check for updates, the app first has to know which Nexus page each mod is (that mod ID string). It only accepts local evidence: what it recorded itself, its own install records, the original archive filename in your download folder, or links written in the mod's readme. It would rather leave the ID empty than guess — a wrong binding means "check for updates" forever compares your files against someone else's version numbers.

Mods it can't identify are collected under "not matched to Nexus", each with "possible matches" candidates underneath — one click binds them. Self-made or ported mods simply don't exist on Nexus; hit "Not on Nexus" and it stops asking.

Author, cover and latest version data is cached for 7 days and only re-fetched once stale. A background pass tops up what's missing at startup, without getting in your way.

CN localization

The CN localization panel swaps English text in English-made mods for the Chinese community translations. Mod text can live in three places: the language tables (cn.w3strings), Chinese hardcoded in scripts, and the menu XML. The panel tells you which of these still contains untranslated English.

  • Only menu pages are translated by default. Mod names and item names are left alone — changing those tends to break in-game references.
  • Equal-length writeback: the translation may not exceed the byte length of the original. If it doesn't fit, the sentence gets shortened first; if it still doesn't fit, the panel tells you exactly how many bytes are short — it never truncates.
  • Mods you've already hand-localized won't be nagged about: when the menu XML is already Chinese, the English entries left in the language tables count as stale leftovers and are merely flagged.
  • The originals are saved away before the first write, so you can restore everything with one click at any time.

Save game backups

Two modes, your call. Full packs up the entire gamesaves folder; Incremental packs only the files that changed since the last backup — handy as a daily one-click habit.

Restoring overwrites your current save games, so it asks for confirmation first, and takes a safety copy of the current saves before anything is touched. Backup archives live in the app's own data directory, not inside the game folder.

Upgrading and your data

Upgrading takes exactly one step: overwrite the old Waass.exe with the new one and double-click it. Your mod list, groups, Nexus IDs, install records, localization originals and save game backups all live in the data folder next to the app — the new build picks them up as they are. No export, no import, no manual file shuffling.

Every launch starts with a quick self-check: is this the first run or a version you just switched to, does this build understand the data format, can the bookkeeping files be read, can anything be written into the data folder. Anything worth knowing is said in the top banner — you never have to wonder whether your data survived.

  • You just switched builds: it says either "existing data checked out (N files read fine)" or exactly which items are broken and what they're called.
  • The data format needs upgrading: the whole set is copied to data/_backup/pre-schema… before anything is touched. To roll back, copy those files into data again.
  • A data file is damaged (power loss, hand-edited JSON): it's renamed to xxx.json.broken-<timestamp> and kept, never deleted. The app carries on as if that record were missing and rebuilds it.
  • You went back to an older build: if data was written by a newer version, the app switches to read-only — everything stays browsable, but not a single byte is written, so the newer data can't be damaged by an older build that doesn't understand it. Switch back to the newer build to keep editing.
  • Settings → About shows "Data format: v…" and a "Run check" button; those two are the most useful facts when reporting a problem.
  • A newer build of the app itself: ten seconds after launch it asks in the background, and only a real update shows in the top banner — "View" opens the release page. "Check for updates" in Settings → About confirms on demand and shows what changed. Results are cached for a day, so relaunching the same day doesn't hit the network again.

When something goes wrong

  • Just made a mistake: there's an "Undo" button right on the banner. Older operations are in the operation log, each one individually undoable.
  • Broke a file: a snapshot was taken before every write (the last 30 are kept), so any operation can be reverted as a whole.
  • Uninstalled the wrong mod: uninstalling never deletes — files go to quarantine and can be brought back.
  • Need the disk space: Settings → Storage & cleanup. Core data (configuration, Nexus records, groups, install records, save game backups, localization originals) is never cleaned up.
  • Installing, enabling or localizing keeps failing: it's almost always permissions. Steam installs the game under C:\Program Files (x86)\Steam\steamapps\common\The Witcher 3 by default, and that path is read-only for a normal user. Close the app, then right-click → "Run as administrator" and try again. If the app finds the game folder unwritable at launch, it says so in an amber banner up front.
  • Moved to another PC: copy the whole program folder and it just works — your data lives in data\ next to the exe. On a machine without the game, it asks you to pick the game folder and everything else keeps working. The mod list always comes from the folder you point it at; the program ships with none of your previous machine's data.
