Waass Mod Manager

《巫师 3：狂猎》次世代版的模组管理器。一个 9 MB 的单文件 exe，双击就能用，
不需要安装，不需要 .NET，不需要别的管理器。

· 它是什么

Mod Organizer 和 RMMR 都能装巫师 3 的模组，但这个游戏有个特点：真正决定
"谁能生效"的，是 mods 文件夹里的三样东西 —— 文件夹名、mods.settings 里的
优先级、以及有没有被 Script Merger 合并过。大多数管理器把这三样当成黑盒，
出问题时你只能对着游戏日志猜。

Waass 把这套东西直接摊在你面前：哪些模组在生效、谁排在谁前面、哪个函数被
两个模组同时改了、哪个菜单文件其实已经没在用了。改之前先给你看清单，改完
之后能一步步撤回去。

· 它能做什么

启用 / 禁用。禁用就是给文件夹名加一个 ~（modHoods 变成 ~modHoods），游戏
引擎只认 mod 开头的文件夹，~ 开头的它根本看不见 —— 等于没装，但文件一个都
没少。好处是不用碰 mods.settings 那个格式极其挑剔的文件，而且加载顺序原样
保留，随时一步切回来。

装包。zip / 7z / rar 拖进来，先看预览：会往游戏目录写哪些文件、哪些会覆盖
已有文件，确认之后才真的写。要往 bin 里塞 DLL 的包会被单独拦下来问一次。
卸载不真删，文件进隔离区，随时能捡回来。

加载顺序。规矩只有一条：数字小的先加载，先加载的在冲突时赢。列表里直接拖，
或者开「加载顺序」面板一次改完。

冲突检查。只查已启用的模组。脚本层面能分清 @wrapMethod（两者通常能共存，
只提示）和 @replaceMethod（后者会把前者整个换掉，给警告）；资源层面只报
界面文件撞车，材质贴图互盖是常态、不报。已经用 Script Merger 合并过的组会被
认出来标绿，不再当成冲突重复提醒。

检查 MOD 更新。不需要 Nexus API Key、不需要登录。程序会先从本地证据推断每个
模组在 Nexus 上的 ID（自己记过的、安装档案、下载目录里的原包名、readme 里的
链接），认不准就空着让你点，绝不猜 —— 绑错 ID 会让"检查更新"永远拿别人的
版本号跟你比。

汉化。模组里的文字可能在三个地方：语言表、脚本里写死的中文、菜单 XML。
程序会告诉你哪一类还有英文没翻，翻完按等长写回（原文占多少字节，译文就不能
超，放不下会明说"还差几字节"，绝不截断）。默认只翻菜单页 —— 模组名和物品名
不动，改了容易和脚本、存档对不上。原始文件永久保留，一键还原。

存档备份。装模组之前自动全量备份一次，之后可以自己做增量。备份放在程序自己
的数据目录里，不占游戏目录。

· 它不动什么

扫描全程只读。写入闸门默认拒绝一切写操作，只对四个位置放开：mods/、dlc/、
菜单配置目录、以及 mods.settings 这一个文件。写入前把受影响的文件快照到
data/snapshots/，游戏正在运行（witcher3.exe 在跑）时直接拒绝写入，每一次写
操作都进撤销栈。

后台服务只监听 127.0.0.1，界面和后台之间用一次性 token，并且校验 Host 头、
拒绝跨站发起的请求。

· 系统要求

Windows 10 / 11（64 位）。巫师 3 次世代版 v5.x，Steam / GOG / Epic 都认。
界面用系统自带的 Microsoft Edge 或已安装的 Chrome，不需要额外装浏览器。

· 怎么开始

1. 下载 exe，双击。Windows 可能提示"未知发布者"，这是未签名程序的正常现象，
   点"更多信息 → 仍要运行"。
2. 程序会自己从 Steam 的库清单、GOG 的注册表、Epic 的安装清单里找游戏目录。
   找不到时它会告诉你该选哪一层 —— 含 bin 文件夹的那一层。
3. 第一次扫描会把封面和作者补齐，几十秒。程序里 设置 → 使用说明 有一份
   按功能写的上手指南，遇到不懂的地方先翻它。

· 一点说明

这个程序不会替你决定该装哪些模组，也不会自动"优化"你的游戏。它做的是把
改动摆到台面上：改了什么、改动前后长什么样、怎么退回去。
